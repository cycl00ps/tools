# Agent deploy playbook — Harbor DHI + Garage

Follow these steps **in order** on a fresh Linux host. Do not skip prerequisites. Prefer the scripts; do not invent alternate image tags unless `versions.env` is updated deliberately.

## Goal

Bring up:

1. Garage (host binary, systemd, single-node S3 on `:3900`)
2. Harbor (all `dhi.io/harbor-*` + `dhi.io/nginx` via Compose)
3. Registry storage → Garage bucket `harbor-images`

## Preconditions (check before changing anything)

```bash
uname -m                    # x86_64 or aarch64
docker version
docker compose version
command -v curl python3 sudo
```

Disk: ensure ≥ 200 GB free on the volume that will hold `/var/lib/garage` and `./data`.

## Step 0 — Configure

```bash
cd <repo-root>
cp .env.example .env
```

Edit `.env` (required):

| Variable | Rule |
|----------|------|
| `HARBOR_HOSTNAME` | DNS name or IP clients will use for `docker login` |
| `HARBOR_EXTERNAL_URL` | `https://<HARBOR_HOSTNAME>` (include port if `HTTPS_PORT` ≠ 443) |
| `HARBOR_ADMIN_PASSWORD` | Strong password; used for UI `admin` user |
| `POSTGRES_PASSWORD` | Strong password for Harbor DB |
| `GARAGE_S3_ENDPOINT` | Host LAN IP, e.g. `http://192.168.1.10:3900` (required for rootless Docker; `host.docker.internal` often fails) |

Leave `GARAGE_ACCESS_KEY` / `GARAGE_SECRET_KEY` empty; bootstrap fills them.

## Step 1 — One-shot deploy

```bash
chmod +x garage/*.sh harbor/prepare.sh scripts/*.sh
./scripts/deploy.sh
```

`deploy.sh` will:

1. `sudo garage/install.sh` — download pinned Garage from `versions.env`, install systemd unit
2. `sudo garage/bootstrap.sh` — create bucket + key, write keys into `.env`
3. `docker login dhi.io` if pulls fail
4. `harbor/prepare.sh` — TLS, secrets, registry config with S3→Garage, htpasswd
5. `docker compose … pull && up -d`

## Step 2 — Verify

```bash
docker compose -f harbor/docker-compose.yml --env-file harbor/.env ps
curl -sk "${HARBOR_EXTERNAL_URL}/api/v2.0/health"
./scripts/smoke-test.sh
```

Success criteria:

- All Compose services `running` / healthy
- Portal reachable at `HARBOR_EXTERNAL_URL` (admin / `HARBOR_ADMIN_PASSWORD`)
- Smoke test push/pull succeeds
- Garage status shows a healthy single node: `sudo garage status`

## Manual path (if not using deploy.sh)

```bash
sudo ./garage/install.sh
sudo ./garage/bootstrap.sh
docker login dhi.io
./harbor/prepare.sh
docker compose -f harbor/docker-compose.yml --env-file harbor/.env pull
docker compose -f harbor/docker-compose.yml --env-file harbor/.env up -d
```

## Important invariants (do not break)

1. **Image pins** live in `versions.env`. Compose reads tags via `harbor/.env` generated by `prepare.sh`.
2. **Never** point `GARAGE_S3_ENDPOINT` at `http://127.0.0.1:3900` from inside containers — use `host.docker.internal` (compose sets `extra_hosts`) or the host LAN IP.
3. **Registry redirect must stay disabled** (`redirect.disable: true` in `harbor/templates/registry/config.yml.tmpl`) for Garage.
4. **Re-run `harbor/prepare.sh`** after any `.env` change that affects hostname, Garage keys, or passwords.
5. DHI images are **nonroot / no shell** — debug with `docker logs` or Docker Debug, not `docker exec … bash`.

## TLS / client trust

Self-signed cert is created at `harbor/secrets/tls/tls.{crt,key}`.

On Docker clients:

- Import/trust the CA/cert, **or**
- Lab-only: configure `insecure-registries` for `HARBOR_HOSTNAME`

`HARBOR_EXTERNAL_URL` host must match the cert CN/SAN and the Host header clients use.

## Backup

| Data | Path |
|------|------|
| Garage objects + meta | `/var/lib/garage/data`, `/var/lib/garage/meta` |
| Harbor DB / redis / jobs / trivy / core | `./data/harbor/` |
| Secrets + generated configs | `.env`, `harbor/secrets/`, `harbor/generated/` |

Stop Harbor before consistent DB backup: `./scripts/down.sh`. Garage may stay up for object copy, or `sudo systemctl stop garage` for cold copy.

## Upgrade

1. Edit `versions.env` (Garage and/or `HARBOR_DHI_TAG` / `NGINX_DHI_TAG`).
2. For Garage: `sudo ./garage/install.sh` (re-downloads binary, restarts unit).
3. `./harbor/prepare.sh`
4. `docker compose -f harbor/docker-compose.yml --env-file harbor/.env pull`
5. `docker compose -f harbor/docker-compose.yml --env-file harbor/.env up -d`

## Troubleshooting

| Symptom | Check |
|---------|--------|
| `ErrImagePull` / unauthorized `dhi.io` | `docker login dhi.io` with Docker Hub user/PAT |
| Registry push fails with S3 errors | `sudo garage status`; keys in `.env`; endpoint reachable from registry container (use LAN IP, not `127.0.0.1` / often not `host.docker.internal` under rootless) |
| `unable to get PrivateKey from PEM type: PRIVATE KEY` | Re-run prepare after deleting `harbor/secrets/core/private_key.pem` — key must be traditional RSA (`BEGIN RSA PRIVATE KEY`) |
| CSRF key length error | `CSRF_KEY` must be exactly 32 characters; re-run `harbor/prepare.sh` |
| Docker TLS unknown authority (rootless) | Place cert at `~/.config/docker/certs.d/<host:port>/ca.crt` (not `/etc/docker/...`) |
| UI login CSRF / cookie issues | Use exact `HARBOR_EXTERNAL_URL`; trust TLS cert |
| Permission errors on volumes | Re-run `harbor/prepare.sh` (sets `a+rwX` on `data/harbor`) |
| Core crash-loop | `docker logs harbor-core` — usually DB/redis/secrets |

```bash
docker compose -f harbor/docker-compose.yml --env-file harbor/.env logs --tail=200 core registry
sudo journalctl -u garage -n 100 --no-pager
```
