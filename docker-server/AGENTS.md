# Agent deploy playbook — Harbor DHI + Garage

Follow these steps **in order** on a fresh Linux host. Do not skip prerequisites. Prefer the scripts; do not invent alternate image tags unless `versions.env` is updated deliberately.

## Goal

Bring up:

1. Garage (host binary, systemd, single-node S3 on `:3900`)
2. Harbor (all `dhi.io/harbor-*` + `dhi.io/nginx` via Compose)
3. Registry storage → Garage bucket `harbor-images`

## Preconditions (check before changing anything)

```bash
uname -m                    # x86_64 or aarch64
docker version
docker compose version
command -v curl python3 sudo
```

Disk: ensure ≥ 200 GB free on the volumes that will hold Garage data dirs and `HARBOR_DATA_DIR` (default `./data/harbor`).

## Step 0 — Configure

```bash
cd <repo-root>
cp .env.example .env
```

Edit `.env` (required / common):

| Variable | Rule |
|----------|------|
| `HARBOR_HOSTNAME` | DNS name or IP clients will use for `docker login` |
| `HARBOR_EXTERNAL_URL` | How browsers reach Harbor. Direct HTTPS: `https://<host>` (include port if ≠ 443). Lab without trusted cert: `http://<host>:<HTTP_PORT>`. Behind Caddy: public `https://<host>` with `NGINX_ENABLE_HTTPS=false` |
| `NGINX_ENABLE_HTTPS` | `true` (default) publishes HTTP+HTTPS on Harbor nginx. `false` = HTTP-only for an external TLS terminator |
| `HTTP_PORT` / `HTTPS_PORT` | Defaults `80` / `443`. Change if taken. `HTTPS_PORT` ignored when `NGINX_ENABLE_HTTPS=false` |
| `PROXY_HTTP_BIND` | Default `0.0.0.0`. Use `127.0.0.1` when Caddy (or similar) proxies to Harbor |
| `HARBOR_DATA_DIR` | Empty ⇒ `<repo>/data/harbor`. Absolute path for DB/redis/core/job_logs/trivy bind mounts. Changing after first deploy does not migrate data |
| `HARBOR_ADMIN_PASSWORD` | Strong password; used for UI `admin` user |
| `POSTGRES_PASSWORD` | Strong password for Harbor DB |
| `GARAGE_META_DIR` / `GARAGE_DATA_DIR` | Default `/var/lib/garage/{meta,data}` |
| `GARAGE_BIN_PATH` / `GARAGE_CONFIG_PATH` | Default `/usr/local/bin/garage`, `/etc/garage.toml` |
| `GARAGE_S3_ENDPOINT` | Host LAN IP, e.g. `http://192.168.1.10:3900` (required for rootless Docker; `host.docker.internal` often fails) |

Leave `GARAGE_ACCESS_KEY` / `GARAGE_SECRET_KEY` empty; bootstrap fills them.

After editing `.env`, always `set -a; source .env; set +a` (or unset a stale exported `HARBOR_EXTERNAL_URL`) before `docker compose` — shell env overrides `--env-file`.

## Step 1 — One-shot deploy

```bash
chmod +x garage/*.sh harbor/prepare.sh scripts/*.sh
./scripts/deploy.sh
```

`deploy.sh` will:

1. `sudo garage/install.sh` — download pinned Garage from `versions.env`, install systemd unit
2. `sudo garage/bootstrap.sh` — create bucket + key, write keys into `.env`
3. `docker login dhi.io` if pulls fail
4. `harbor/prepare.sh` — TLS (if HTTPS enabled), secrets, registry config with S3→Garage, htpasswd
5. `docker compose … pull && up -d` (adds `docker-compose.https.yml` when `NGINX_ENABLE_HTTPS=true`)

## Step 2 — Verify

```bash
set -a; source harbor/.env; set +a
docker compose ${COMPOSE_FILES} --env-file harbor/.env ps
curl -sk "${HARBOR_EXTERNAL_URL}/api/v2.0/health"
./scripts/smoke-test.sh
```

Success criteria:

- All Compose services `running` / healthy
- Portal reachable at `HARBOR_EXTERNAL_URL` (admin / `HARBOR_ADMIN_PASSWORD`)
- Smoke test push/pull succeeds
- Garage status shows a healthy single node: `sudo garage status`

## Manual path (if not using deploy.sh)

```bash
sudo ./garage/install.sh
sudo ./garage/bootstrap.sh
docker login dhi.io
set -a; source .env; set +a
./harbor/prepare.sh
set -a; source harbor/.env; set +a
docker compose ${COMPOSE_FILES} --env-file harbor/.env pull
docker compose ${COMPOSE_FILES} --env-file harbor/.env up -d
```

`COMPOSE_FILES` is written by `prepare.sh` (e.g. `-f harbor/docker-compose.yml -f harbor/docker-compose.https.yml`).

## Important invariants (do not break)

1. **Image pins** live in `versions.env`. Compose reads tags via `harbor/.env` generated by `prepare.sh`.
2. **Never** point `GARAGE_S3_ENDPOINT` at `http://127.0.0.1:3900` from inside containers — use `host.docker.internal` (compose sets `extra_hosts`) or the host LAN IP.
3. **Registry redirect must stay disabled** (`redirect.disable: true` in `harbor/templates/registry/config.yml.tmpl`) for Garage.
4. **Re-run `harbor/prepare.sh`** after any `.env` change that affects hostname, Garage keys, passwords, ports, HTTPS mode, or data paths.
5. DHI images are **nonroot / no shell** — debug with `docker logs` or Docker Debug, not `docker exec … bash`.

## TLS / client trust

When `NGINX_ENABLE_HTTPS=true`, a self-signed cert is created at `harbor/secrets/tls/tls.{crt,key}`.

On Docker clients:

- **HTTPS:** import/trust the cert, **or** lab-only `insecure-registries` for `host` or `host:HTTPS_PORT`
- **HTTP lab** (`HARBOR_EXTERNAL_URL=http://…`): add `host:HTTP_PORT` to `insecure-registries` (rootless Docker: `~/.config/docker/daemon.json`, then `systemctl --user restart docker`)
- **Behind Caddy:** clients trust Caddy’s cert; Harbor nginx stays on `PROXY_HTTP_BIND:HTTP_PORT` only

`HARBOR_EXTERNAL_URL` host (and port) must match what browsers and `docker login` use. For direct HTTPS, that host must also match the cert CN/SAN.

### Caddy example (HTTP-only Harbor)

```
registry.example.local {
  reverse_proxy 127.0.0.1:8088
}
```

With `.env`: `NGINX_ENABLE_HTTPS=false`, `PROXY_HTTP_BIND=127.0.0.1`, `HTTP_PORT=8088`, `HARBOR_EXTERNAL_URL=https://registry.example.local`.

## Backup

| Data | Path |
|------|------|
| Garage objects + meta | `$GARAGE_DATA_DIR`, `$GARAGE_META_DIR` (defaults under `/var/lib/garage/`) |
| Harbor DB / redis / jobs / trivy / core | `$HARBOR_DATA_DIR` (default `./data/harbor/`) |
| Secrets + generated configs | `.env`, `harbor/secrets/`, `harbor/generated/` |

Stop Harbor before consistent DB backup: `./scripts/down.sh`. Garage may stay up for object copy, or `sudo systemctl stop garage` for cold copy.

## Upgrade

1. Edit `versions.env` (Garage and/or `HARBOR_DHI_TAG` / `NGINX_DHI_TAG`).
2. For Garage: `sudo ./garage/install.sh` (re-downloads binary, restarts unit).
3. `./harbor/prepare.sh`
4. `set -a; source harbor/.env; set +a`
5. `docker compose ${COMPOSE_FILES} --env-file harbor/.env pull && docker compose ${COMPOSE_FILES} --env-file harbor/.env up -d`

## Troubleshooting

| Symptom | Check |
|---------|--------|
| `ErrImagePull` / unauthorized `dhi.io` | `docker login dhi.io` with Docker Hub user/PAT |
| Registry push fails with S3 errors | `sudo garage status`; keys in `.env`; endpoint reachable from registry container (use LAN IP, not `127.0.0.1` / often not `host.docker.internal` under rootless) |
| `unable to get PrivateKey from PEM type: PRIVATE KEY` | Re-run prepare after deleting `harbor/secrets/core/private_key.pem` — key must be traditional RSA (`BEGIN RSA PRIVATE KEY`) |
| CSRF key length error | `CSRF_KEY` must be exactly 32 characters; re-run `harbor/prepare.sh` |
| Docker TLS unknown authority (rootless) | Place cert at `~/.config/docker/certs.d/<host:port>/ca.crt` (not `/etc/docker/...`) |
| UI login CSRF / cookie issues | Lab HTTP: `HARBOR_EXTERNAL_URL=http://…:8088`. Behind Caddy: public `https://…` + `NGINX_ENABLE_HTTPS=false`. Unset stale shell `HARBOR_EXTERNAL_URL` before compose |
| Permission errors on volumes | Re-run `harbor/prepare.sh` (sets `a+rwX` on `HARBOR_DATA_DIR`) |
| Core crash-loop | `docker logs harbor-core` — usually DB/redis/secrets |

```bash
set -a; source harbor/.env; set +a
docker compose ${COMPOSE_FILES} --env-file harbor/.env logs --tail=200 core registry
sudo journalctl -u garage -n 100 --no-pager
```
